# K-Terminal Evidence-First Research Methodology Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace personality-driven stock opinions with deterministic, evidence-gated research rules that trace demand, supply-chain bottlenecks, company attribution, financial quality, security readiness, falsifiers, and date-aligned outcomes.

**Architecture:** Keep the existing `DataEnvelope -> EvidencePack -> FindingSynthesisReport -> DiagnosticDebate -> OutcomeJournal` pipeline, but insert typed method rules, a claim-level evidence graph, falsifiable thesis pillars, and five deterministic validation responsibilities. Research-voice posts are append-only inputs, never trading signals. Company thesis and security readiness are calculated separately, and missing price, valuation, filing, or provenance data must stop the relevant conclusion.

**Tech Stack:** Next.js 16, React 19, TypeScript, Vitest, Testing Library, existing filesystem runtime stores, existing `DataEnvelope<T>`, existing `SignalVersion`, lucide-react, semantic `kt-*` design tokens.

---

## 1. Product Boundary

This work builds a research audit system, not an automated analyst persona.

### Allowed outputs

- `confirming`
- `mixed`
- `deteriorating`
- `insufficient_data`
- `not_decision_grade`
- explicit missing inputs, stale evidence, contradictions, and falsifiers

### Forbidden outputs

- buy, sell, entry, target price, position size, expected return, guaranteed return
- a score generated by an LLM
- a conclusion produced by agent voting
- a named-person imitation such as "Buffett Agent" or "Serenity Agent"
- treating mention count, follower count, likes, or self-reported returns as alpha
- treating price appreciation as confirmation of a company thesis
- converting `unclear` to `neutral`
- creating a security conclusion without current price and valuation evidence

### Explicitly deferred

- `better-sqlite3` and production database migration
- public-web scraping and Selenium ingestion
- external LLM calls
- weighted methodology scores
- automatic production eligibility
- portfolio orders and paper trading

The first implementation must stabilize contracts and deterministic rules on the existing runtime-file boundary. A later storage work order may add SQLite behind the same interfaces after schema and migration behavior are proven.

## 4. Acceptance Criteria

### P0

- Existing EvidencePack synthesis/debate UI calls valid API routes.
- Outcome records cannot fall back to AAPL.
- Observation starts at the source date and exact trading-day horizon.
- A not-yet-reached horizon remains pending.
- Market and sector excess returns remain separate and versioned.
- Old outcome revisions remain readable.
- One observation never changes confidence automatically.

### P1

- Method rules are named, deterministic, unweighted, and research-only.
- Supply-chain links distinguish verified, inferred, hypothesis, and contradicted states.
- Research posts are append-only and source-linked.
- Unresolved symbols are not guessed.
- Claims link only to relevant evidence.
- Thesis pillars include explicit confirm, warning, and break conditions.
- Company thesis and security readiness are separate.
- Missing price/valuation prevents a decision-grade security status.
- Five validation responsibilities use ordered veto gates, not voting.
- UI shows data gaps before conclusions.

### Non-regression

- Existing Strategy, Reliability, Alerts, Watchlist, and Backtest tabs still render.
- All financial API responses remain `DataEnvelope<T>`.
- Null values remain null.
- No live trading or paper trading path is added.
- All required verification commands pass.

## 5. Failure Conditions

Reject the implementation if any of these occur:

1. A named investor persona generates a score or status.
2. Multiple LLM outputs are averaged or voted into a conclusion.
3. Mention count or engagement affects thesis confidence.
4. A supply-chain edge is marked verified without evidence.
5. A claim receives every EvidencePack by default.
6. Price appreciation confirms a company pillar.
7. Missing price or valuation still yields a security conclusion.
8. `unclear` is converted to `neutral`.
9. Deleted or revised source posts overwrite history.
10. A missing outcome asset falls back to any default ticker.
11. A future horizon is marked observed early.
12. Market and sector benchmark returns are merged into one value.
13. One observed result changes confidence.
14. SQLite is added before the file-store contract tests pass.
15. UI displays sample research as real provider data.
16. Build passes but browser QA is not performed or is misreported.
